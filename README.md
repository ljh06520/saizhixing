# 赛知行

赛知行是我们参加全国高校 AI Web 开发挑战赛做的作品。准备比赛时，报名条件、参赛人数和提交材料往往得从几份通知里分别找。碰到补充通知，先要弄清它适用哪个阶段，再看有没有替代原来的规定。我们把这些操作放进一个工作区，查到一条要求就可以点开原文，核对后再列进准备清单。

我们来自广州商学院，团队是 **WEB玩家（B组）**。成员为罗锦豪、叶钧锴、庄金源，指导教师为谭永恒。

## 在本机运行

需要 Node.js 22.2 或更高版本、pnpm 和 Git。以下命令从你准备存放项目的目录执行。

```powershell
git clone https://github.com/ljh06520/saizhixing.git
cd saizhixing
pnpm install --frozen-lockfile
pnpm verify
pnpm start --hostname 127.0.0.1 --port 3002
```

`pnpm verify` 会执行检查和生产构建。启动后打开 [本地工作台](http://127.0.0.1:3002)，默认无需配置密钥。开发时可用 `pnpm dev`，地址以终端输出为准。重新构建前先停止开发服务，避免同时使用 `.next`。

## 评审可以这样体验

1. 点击「先体验演示」，进入「证据问答」，输入“我需要准备哪些提交材料？”。点击回答里的编号，打开对应原文。
2. 在「赛事资料」查看来源和适用阶段，再从工作台打开规则冲突。对比两份来源时，可以看到各自的数值和原文。
3. 到「规则审阅」执行本地提取，回到工作台编辑人数，看看人数核对如何跟着变化。
4. 到「材料清单」勾选一项，然后导出 Markdown。也可以选一个 PDF 试试页数预检。

内置演示摘录未经官网核验。回归测试里的通知另行编写，用于复现边界情况。正式报名请以组委会公布的信息为准。

## 我们怎么做的

浏览器用 IndexedDB 保存资料、规则和勾选状态。PDF.js 提取文本并保留页码。问答把当前工作区的快照交给本机 Next.js 接口，按阶段筛资料，再做中文词法排序。引用带文档版本和原文位置，适合回到通知核对。各工作区资料独立保存，切换浏览器或端口后需要重新导入。

问答的最后一步，我们选择了一种容易复核的做法。模型选取逐字摘录，服务端检查编号和引文，校验失败则展示原文片段。可用工具包括检索、规则比较、条件核对和清单生成。人数等可计算条件由代码比较，复杂例外需要读原文。

材料预检检查 README 章节关键词、PDF 页数和浏览器能读取的视频参数。团队还要自己审核文件正文和演示内容。扫描 PDF 需要先用其他工具转成可读文本。本项目当前以本机运行和演示为主。

### 可选 DeepSeek 模式

在项目根目录把 `.env.example` 复制为 `.env.local`。如果已有 `.env.local`，直接编辑。填入自己的密钥并重启服务。

```dotenv
AI_ENABLED=true
DEEPSEEK_API_KEY=在本机填写自己的密钥
MODEL_ID=deepseek-chat
```

开启后，证据问答可调用模型和工具，规则审阅可使用 AI 提取。问答会向供应商发送问题、必要画像和候选证据，AI 规则提取会发送资料正文。真实密钥放在本机 `.env.local`。默认模式由本机服务完成检索和规则解析。

## 测试与材料

我们最初的浏览器回归做了 59 项，其中两项失败。连续提问会把上一轮调用留在面板上，删除确认框也无法用 Escape 退出。修复后做了 8 项针对性复测，均通过。统一自动验收 9 组、确定性规则与引用 54 项也已通过。历史模型对照和本轮复测的范围见各自记录。
